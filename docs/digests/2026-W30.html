This week in CSSWG

The 2026-07-22 telecon delivered five resolutions — scroll snap caught up with single-axis scrollers, masonry settled an out-of-flow question, and filter effects cleaned up two SVG-era leftovers — while the mixins @locals design and the utility-class wildcard selector had their busiest week yet.

Notable

  • Scroll snap learns about single-axis scrollers (#14018)
    • Background: the group previously resolved to allow true single-axis scrollers (one axis scroll, the other clip no longer coerced to hidden); specs written assuming "a scroller scrolls both axes" are being updated one by one.
    • Why it matters: snap behavior in nested or one-axis scroller setups becomes predictable — a snap position attaches, per axis, to the nearest ancestor that actually scrolls that axis, so a horizontal scroll-snap-type on a vertical-only scroller no longer swallows the snap.
    • Summary: RESOLVED: "Snap positions affect the nearest ancestor scroll container in each axis they align to" (vmpstr's proposal, flackr's wording). The same call also resolved that coincident snap candidates tie-break in flat-tree order rather than DOM order, so shadow-DOM slotting no longer changes which element you snap to.
    • Related: #13832
  • Masonry: out-of-flow items follow fill-reverse (#13931)
    • Background: in a grid-lanes container with fill-reverse, items fill from the end of the stacking axis — so where should the static position of an absolutely-positioned child land? See CSS Masonry.
    • Why it matters: one more layout detail of the incoming masonry feature nailed down, consistently with what flexbox already does under its reversals.
    • Summary: RESOLVED to reverse static positions in grid-lanes, following flexbox precedent; TabAtkins and emilio noted static positions outside block layout are near-useless, so consistency and implementation simplicity won.
    • Related: CSS Masonry
  • Filter effects: two SVG-era cleanups (#13949)
    • Background: SVG 1.1's <filter href> inheritance was accidentally dropped from the Filter Effects spec and, it turns out, barely implemented anywhere; separately, the filter region for CSS boxes referencing SVG filters was never defined, and engines diverged between border box and ink-overflow bounds.
    • Why it matters: the first makes the accidental removal official (only Firefox ever shipped it); the second stops engines from exposing undefined ink-overflow bounds — an interop and privacy-adjacent cleanup for anyone using SVG filters on HTML.
    • Summary: RESOLVED to drop the href attribute on <filter>, and to define the filter region as the border box (bounding client rects for split inlines) — smfr flagged authors may need to extend the region when descendants overflow.
    • Related: #13964

  • #14004 @locals hygienic rewriting — the busiest design thread of the week: LeaVerou wants @locals at the sheet top level for private variables, kbabbitt's mental model is "hoisted declarations with secret names".
  • #10001 wildcard selectors for utility classes — LeaVerou pushed .foo-* with future extensions sketched; grammar conflicts with existing attribute selectors remain the sticking point.
  • #14143 :hover / :active top-layer propagation — mfreed7 pointed back at the original resolution's rationale; emilio listed what that discussion never considered.
  • #12799 Selectors 4 toward CR — svgeesus pushing an updated WD incorporating horizontal review; css-syntax-3 likely republishes first.
  • #14192 / #14193 — AccentColor cycles (color: AccentColor; accent-color: currentColor), with LeaVerou proposing a general "resolve against the parent" design principle.
  • #13980 ::interest-button — mfreed7 surveyed design systems for existing "info icon" cow paths after the July 22 discussion.
