This month in CSSWG

This is an in-progress August snapshot, covering the mirror through August 27. The month has been unusually rich in author-facing design work: customizable form controls moved from a broad default-styling debate into concrete UA rules; Selectors gained a narrowly defined class-prefix syntax; and native mixins shed several pieces of syntax while gaining private variables. The group also opened new design space for 2D gradients and sticky scroll animations, while treating masonry reading order and line clamping as accessibility questions rather than layout details alone.

Notable this month

  • Customizable <select> moves from “styleable” to usable by default (#14256)
    • Background: Apple proposed that appearance: base controls should be production-usable before authors add CSS, backed by a survey of design systems. The proposal covered spacing, rounded corners, typography, icons, picker sizing, colors, shadows, and animation rather than treating each default in isolation.
    • Why it matters: customizable <select> is becoming a real authoring surface, but a bare primitive still leaves every design system to rediscover overflow, writing-mode, accessibility, and disabled-state rules. Better defaults reduce that burden; overly opinionated defaults create more CSS to undo and can become dated.
    • Summary: the joint meeting did not adopt the full visual proposal. Jen Simmons argued that polished defaults reduced one example from 66 to 28 author CSS lines and protected low-budget sites from missing edge cases (minutes); una and others warned that “timeless” styling is impossible and animations or shadows are expensive to reverse. The work was split into testable pieces. The picker now uses max-block-size: 100dvb with safe overflow alignment (#14172 resolution); traditional <select> markup gets a wrapper, subsequently named ::field-content, so long labels can clip without pushing out the picker icon (#14323 resolution, rename); and selected text now inherits overflow controls (#14255 resolution). Whether ::field-content matches under appearance: auto is still open. Internal icons are excluded from the accessibility tree (#14316 resolution), while input, select, and option gained block-axis centering, with checkbox/radio compatibility still to be checked (#14319 resolution).
    • Related: #14249, #14250, #14254, #14317, Anchor Positioning
  • A narrowly defined class-prefix selector lands (#10001)
    • Background: utility frameworks, icon libraries, and author conventions commonly encode a family in classes such as pt-6, bi-alarm, or btn-primary. Today, sharing rules across that family requires another class, generated selector lists, or the awkward [class^=…], [class*=…] pattern.
    • Why it matters: the new dot-identifier-hyphen-wildcard form lets a library target the common behavior of every hyphen-separated class in a family without enumerating it. It directly affects Tailwind/Bootstrap-style APIs, icon sets, and BEM-like naming, but also risks blessing one naming convention and complicating selector matching.
    • Summary: the group accepted the proposed class-selector form, limited specifically to a hyphen-separated prefix (resolution); arbitrary wildcard prefixes remain out. The draft followed on August 18, but public review reopened the design rationale. Critics argued that the syntax privileges utility frameworks, implies namespace semantics that HTML class tokens do not have, and may match BEM classes unexpectedly; proponents answered that the proposal targets an established, otherwise costly pattern rather than general substring matching. Even the boundary remains live: #14291 asks whether a trailing hyphen alone matches, and whether a double-hyphen BEM class belongs to the family.
    • Related: #14224, #14289, #14371
  • Native mixins converge on @mixin + @private, with call-site evaluation (#14243)
    • Background: the draft had accumulated overlapping constructs: @mixin and @macro, an @result wrapper, and pseudo-private custom-property conventions. A meta discussion treated these as one authoring-model problem rather than independent syntax bikesheds.
    • Why it matters: this is the difference between a feature that merely copies declarations and one that can support reusable component libraries without variable-name collisions. Fewer constructs make native mixins easier to learn; private variables and predictable units make them safer to compose.
    • Summary: the August 4 F2F resolved to keep @mixin, drop @macro, remove @result, and put hygienically rewritten custom properties in an @private block nested inside a style rule (four resolutions). A fresh objection asked to retain @macro as a Sass-like selector-extension feature, but the issue was closed because that behavior was never part of the construct; selector extension would be separate (#14387). A later resolution fixed a subtler surprise: function arguments, defaults, locals, and results are all evaluated where the function is called, so 1em, random(), and other context-dependent values do not change meaning merely because an argument is typed (#14338 resolution).
    • Related: #14004, #13727, #14212
  • 2D gradients: mesh compatibility research pushes CSS toward freeform-gradient() (#7648)
    • Background: the web can fake soft 2D color fields by layering radial gradients or drawing into Canvas/WebGL, but cannot express a true mesh/freeform gradient as a CSS image. The thread distinguishes grid-based mesh gradients with Bézier-controlled patches from freeform gradients authored as colored points.
    • Why it matters: a CSS image function would make designer-style color meshes responsive, animatable, and themeable without shipping raster assets or custom rendering code. The choice of primitive also determines whether authors get a short list of color points or an SVG/PDF-like matrix that usually needs tooling.
    • Summary: no resolution yet, but August materially changed the direction. Tests against SwiftUI and PDF exposed rendering artifacts and algorithm differences; rasterizing for PDF export was considered acceptable. Tab Atkins moved toward freeform-gradient() because its authoring model matches existing gradients—color plus position—while mesh syntax carries control points and color-smoothing choices (comment). Bramus' prototypes then showed that freeform output can map to tensor-product patches and PDF, reducing the compatibility objection. The remaining split is whether CSS should standardize the simple freeform surface first or define one structured model that can also cover full meshes.
    • Related: css-images-5
  • Masonry reading order enters explicit incubation, not normative shipping (#5675)
    • Background: display: grid-lanes can place visually adjacent cards far apart in DOM order. Earlier work agreed that masonry behaves more like Grid than Flexbox, but that did not supply a reading/focus order for irregular lanes.
    • Why it matters: visual masonry can otherwise send keyboard and assistive-technology users through a page in an order that no longer matches the layout. The problem grows when zoom or responsive reflow changes the number of lanes, so a plausible desktop ordering is not enough.
    • Summary: after proposals based on lane-by-lane traversal and “reading regions,” accessibility reviewers still found cases where focus could jump across columns or change under reflow. The group therefore chose incubation: add a per-lane value to reading-flow, and publish the broader algorithm only as an experimental informative appendix in Grid L3 while collecting feedback (resolution). Prototyping is encouraged, but public shipping must return to the WG. In parallel, Grid Lanes gained a shorthand direction, item-slack became fit-tolerance, and gap decorations were defined lane by lane; whether Grid and Grid Lanes can subgrid each other remains open in #14390.
    • Related: CSS Masonry, #10884, #12023, #14153, #14156
  • Scroll-driven animations get a first-class sticky range (#14181)
    • Background: scrollytelling effects often begin when a position: sticky element becomes stuck and end when it becomes unstuck. Authors can approximate this with view-timeline offsets, but must manually keep those offsets synchronized with sticky insets and surrounding layout.
    • Why it matters: animation-range: stuck turns a common multi-property calculation into an author-facing state. It makes sticky chapter transitions, pinned horizontal scrollers, and other scroll effects less fragile under responsive layout changes.
    • Summary: the group resolved to start specifying animation-range: stuck (resolution). The minutes favored a range rather than a new timeline because authors may want a transition from the stuck point into another existing range. The first follow-up immediately found unresolved semantics: an element constrained at both edges can have two disjoint stuck intervals, suggesting stuck-start and stuck-end, and a non-sticky subject may need an inactive range. Other Interop-facing work fixed progress-timeline behavior at animation-range boundaries (#12134); fixed-position view-timeline subjects remain undefined in #14296.
    • Related: Scroll-driven Animations, #13608
  • line-clamp reverses course on hidden text for assistive technology (#12859)
    • Background: the group had resolved in February that clamped-away content should be absent from both visual rendering and screen readers. Accessibility feedback then highlighted low-vision users who combine enlarged text with VoiceOver or HoverText: zoom can leave them with only a few visible words even when the full text is present in the DOM.
    • Why it matters: line clamping is common in cards, tables, and “read more” previews. Whether hidden lines remain focusable, searchable, selectable, and exposed through accessibility APIs can determine whether content is merely visually shortened or genuinely unavailable.
    • Summary: the August discussion found conflicting author intents—sometimes clamping is presentational, sometimes it intentionally hides a long article—but rejected making the accessibility tree diverge from focus and selection behavior. The new resolution makes line-clamp behave like overflow-y: clip, with follow-up actions for accessibility review and documentation (resolution). This reverses February's hidden-content rule and aligns exposure with the current overflow model. Rendering details also converged around existing overflow behavior, including one-axis clipping around rounded corners (#14067 resolution).
    • Related: #14047, #13670
  • East Asian punctuation trimming expands from presets to composable controls (#13789)
    • Background: text-spacing-trim used a short list of compound values, each controlling several distinct operations: punctuation at paragraph starts, wrapped line starts, line ends, and adjacent punctuation runs. Even internationalization specialists reported that the presets were difficult to remember and could not express every combination.
    • Why it matters: this property controls whether Chinese and Japanese punctuation leaves unwanted half-em gaps at line boundaries. More explicit values let publishers choose typography for their language and house style instead of accepting a bundled preset.
    • Summary: the group adopted an expanded syntax that combines start, end, and adjacent-punctuation controls while retaining compound keywords, plus auto (resolution). The landing is not clean: the resolution pointed to syntax in the IRC log rather than quoting it, and the issue's i18n reporter immediately questioned whether the adopted form had received enough review and whether adjacent-punctuation behavior belongs in a separate property. The direction—expose the constituent controls—is set; names and grouping may still move.
    • Related: #14345, css-text-4

Still contested

  • #14143 top-layer :hover / :active propagation — August's test case confirmed that events, :hover, and :has(:hover) expose different trees; the August 20 telecon still did not resolve whether an open <select> should remain hovered.
  • #14125 detecting an installed application context — CSSWG prefers extending display-mode so it can match an application context and fullscreen simultaneously; Web App Manifest participants question whether that represents “installed” rather than merely “displayed like an app.”
  • #5292 inherited background color — customizable controls need a usable page background, but currentBackgroundColor, an inherited canvas-color, and reuse of accent colors have different transparency and naming problems; the August 26 call produced no resolution.
  • #14307 :has-slotted and fallback content — aligning with assignedNodes({flatten:true}) would count fallback content, but doing so consistently across nested slots risks shadow-tree encapsulation leaks.
  • #14266 base URL for CSS-defined URL patterns — document-relative patterns fit application routing, but make external stylesheet parsing depend on the embedding document and can expose URL components; origin-relative matching is the leading fallback.
  • #14079 weighted random-item() values — the capability is wanted, but percentage-first versus value-first syntax and colon/comma grouping remain open.
