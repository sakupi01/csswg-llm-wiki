## This week in CSSWG

The 2026-07-22 telecon delivered five resolutions — scroll snap caught up with
single-axis scrollers, masonry settled an out-of-flow question, and filter
effects cleaned up two SVG-era leftovers — while the mixins `@locals` design
and the utility-class wildcard selector had their busiest week yet.

## Notable

- **Scroll snap learns about single-axis scrollers** ([#14018](https://github.com/w3c/csswg-drafts/issues/14018))
  - **Background:** the group previously resolved to allow true single-axis scrollers (one axis `scroll`, the other `clip` no longer coerced to `hidden`); specs written assuming "a scroller scrolls both axes" are being updated one by one.
  - **Why it matters:** snap behavior in nested or one-axis scroller setups becomes predictable — a snap position attaches, per axis, to the nearest ancestor that actually scrolls that axis, so a horizontal `scroll-snap-type` on a vertical-only scroller no longer swallows the snap.
  - **Summary:** [RESOLVED](https://github.com/w3c/csswg-drafts/issues/14018#issuecomment-5048738521): "Snap positions affect the nearest ancestor scroll container in each axis they align to" ([vmpstr](../people/vmpstr.md)'s proposal, [flackr](../people/flackr.md)'s wording). The same call also resolved that coincident snap candidates [tie-break in flat-tree order](https://github.com/w3c/csswg-drafts/issues/13832#issuecomment-5048660954) rather than DOM order, so shadow-DOM slotting no longer changes which element you snap to.
  - **Related:** [#13832](https://github.com/w3c/csswg-drafts/issues/13832)
- **Masonry: out-of-flow items follow `fill-reverse`** ([#13931](https://github.com/w3c/csswg-drafts/issues/13931))
  - **Background:** in a `grid-lanes` container with `fill-reverse`, items fill from the end of the stacking axis — so where should the *static position* of an absolutely-positioned child land? See [CSS Masonry](../features/masonry.md).
  - **Why it matters:** one more layout detail of the incoming masonry feature nailed down, consistently with what flexbox already does under its reversals.
  - **Summary:** [RESOLVED](https://github.com/w3c/csswg-drafts/issues/13931#issuecomment-5048621763) to reverse static positions in grid-lanes, following flexbox precedent; [TabAtkins](../people/tabatkins.md) and [emilio](../people/emilio.md) noted static positions outside block layout are near-useless, so consistency and implementation simplicity won.
  - **Related:** [CSS Masonry](../features/masonry.md)
- **Filter effects: two SVG-era cleanups** ([#13949](https://github.com/w3c/csswg-drafts/issues/13949))
  - **Background:** SVG 1.1's `<filter href>` inheritance was accidentally dropped from the Filter Effects spec and, it turns out, barely implemented anywhere; separately, the *filter region* for CSS boxes referencing SVG filters was never defined, and engines diverged between border box and ink-overflow bounds.
  - **Why it matters:** the first makes the accidental removal official (only Firefox ever shipped it); the second stops engines from exposing undefined ink-overflow bounds — an interop and privacy-adjacent cleanup for anyone using SVG filters on HTML.
  - **Summary:** RESOLVED to [drop the `href` attribute on `<filter>`](https://github.com/w3c/csswg-drafts/issues/13949#issuecomment-5048768304), and to [define the filter region as the border box](https://github.com/w3c/csswg-drafts/issues/13964#issuecomment-5048873342) (bounding client rects for split inlines) — [smfr](../people/smfr.md) flagged authors may need to extend the region when descendants overflow.
  - **Related:** [#13964](https://github.com/w3c/csswg-drafts/issues/13964)
