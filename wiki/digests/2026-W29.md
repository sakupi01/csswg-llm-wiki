## This week in CSSWG

The 2026-07-15 telecon spent its three resolutions on interop housekeeping —
two "spec is right, fix the tests" calls for scroll-driven animations and one
genuinely author-facing ruling: `::first-line`/`::first-letter` won't apply
inside text inputs. Around it, the customizable `<select>` hover debate and
the `border-shape` design threads kept running hot.

## Notable

- **`::first-line` / `::first-letter` won't apply inside text inputs** ([#13926](https://github.com/w3c/csswg-drafts/issues/13926))
  - **Background:** Blink half-accidentally supported `::first-line` on `input`/`textarea`; the internal layout of form controls is unspecced and differs across engines.
  - **Why it matters:** an author-visible selector rule is now explicit — these pseudo-elements do nothing on text inputs, the same way `::before`/`::after` don't apply.
  - **Summary:** in the call, lea pressed the author-expectation side ("if they're using it they're expecting it to work") while [emilio](../people/emilio.md) argued there's no interoperable internal layout to hook them onto — password-input internals, `::placeholder` interactions, none of it is specced. [RESOLVED](https://github.com/w3c/csswg-drafts/issues/13926#issuecomment-4983249817): they don't apply "for now", to be revisited once these controls have better-defined layout.
  - **Related:** [#14190](https://github.com/w3c/csswg-drafts/issues/14190) (the flip side: making `align-content` center a block `<button>`'s content — [bfgeek](../people/bfgeek.md) and [emilio](../people/emilio.md) converged on a proposal this week)
- **Scroll-driven animations: two "fix the tests" rulings** ([#11644](https://github.com/w3c/csswg-drafts/issues/11644))
  - **Background:** Interop-2026 test work keeps flushing out places where Chromium's shipped behavior and the spec disagree — see [Scroll-driven Animations](../features/scroll-driven-animations.md).
  - **Why it matters:** both affect the Web Animations API surface of scroll/view timelines: `ViewTimelineOptions.inset` defaults to `auto` (which opts into `scroll-padding`), and shorthand serialization of coordinated value lists stays as specced.
  - **Summary:** RESOLVED [spec is right, fix the tests](https://github.com/w3c/csswg-drafts/issues/11644#issuecomment-4982811693) for the `inset` default (Chrome's empty-array default was a years-old accident), and RESOLVED [spec is right, fix tests, add animated-value tests](https://github.com/w3c/csswg-drafts/issues/13500#issuecomment-4982841033) for the serialization question. A third fix is queued as an async resolution: [auto-aligning a start time should apply a pending playback rate](https://github.com/w3c/csswg-drafts/issues/14173).
  - **Related:** [Scroll-driven Animations](../features/scroll-driven-animations.md), [#13500](https://github.com/w3c/csswg-drafts/issues/13500)
