## This month in CSSWG

June's throughline was **implementations catching up to specs, and specs
reacting**. Selected for developer impact rather than comment volume: the
`::interest-button` default reversed, scroll-driven animations got a semantics
pass, Link Params reached FPWD, and randomness matured in Values 5 — while the
loud-but-low-impact CSS Color 5 serialization threads are gathered under "Still
contested." 28 resolutions landed across ~92 active agenda items.

## Notable this month

- **`::interest-button` reverses course on turning itself on** ([#13980](https://github.com/w3c/csswg-drafts/issues/13980))
  - **Background:** `::interest-button` surfaces an affordance for interest invokers (`interestfor`). Early June RESOLVED to gate it behind an [inline media condition (`display: if(media())`)](https://github.com/w3c/csswg-drafts/issues/13980#issuecomment-4682270794).
  - **Why it matters:** whether a layout-affecting control is on by default is a page-breaking decision for every author using interest invokers — a live cross-vendor question, not a detail.
  - **Summary:** after developer conversations at CSS Day, the group [voided that resolution](https://github.com/w3c/csswg-drafts/issues/13980#issuecomment-4801238759). [LeaVerou](../people/lea.md) argued authors would simply turn it off — anything that affects layout by default breaks pages, and an opt-out adds more UX noise (stray tab stops, tooltips among real targets) than it solves. How it turns on is open again (37 comments this month).
  - **Related:** UA-latitude vs. "layout-affecting defaults get disabled" — the tension to watch as interest invokers ship.
- **Scroll-driven animations get a semantics pass** ([#13817](https://github.com/w3c/csswg-drafts/issues/13817))
  - **Background:** several scroll/view-timeline timing rules were underspecified, producing "why did my scroll animation jump?" surprises.
  - **Why it matters:** these are exactly the edge cases authors hit wiring animations to scroll; the fixes change observable behavior.
  - **Summary:** RESOLVED — [timeline-source changes apply asynchronously](https://github.com/w3c/csswg-drafts/issues/13480#issuecomment-4614087368); [auto-rewind has no effect when the timeline is unresolved](https://github.com/w3c/csswg-drafts/issues/13817#issuecomment-4614196831) with a new [`play-always` trigger](https://github.com/w3c/csswg-drafts/issues/13643#issuecomment-4613983278); [`startOffset`/`endOffset` are nullable](https://github.com/w3c/csswg-drafts/issues/13844#issuecomment-4614158334); [scroll-timeline names are loosely matched](https://github.com/w3c/csswg-drafts/issues/13974#issuecomment-4672119742).
  - **Related:** [#13480](https://github.com/w3c/csswg-drafts/issues/13480), [#13643](https://github.com/w3c/csswg-drafts/issues/13643), [#13844](https://github.com/w3c/csswg-drafts/issues/13844), [#13974](https://github.com/w3c/csswg-drafts/issues/13974), [#13818](https://github.com/w3c/csswg-drafts/issues/13818)
- **Link Params reaches First Public Working Draft** ([#14028](https://github.com/w3c/csswg-drafts/issues/14028))
  - **Background:** Link Params adds a `param()` function for parameterizing links/URLs.
  - **Why it matters:** a new spec crossing FPWD is the signal that a feature is officially on the standards track — worth a developer's radar.
  - **Summary:** RESOLVED to [publish Link Params as FPWD](https://github.com/w3c/csswg-drafts/issues/14028#issuecomment-4672083352) and to [require `param()` to carry at least two values](https://github.com/w3c/csswg-drafts/issues/13767#issuecomment-4732890422).
  - **Related:** [#13767](https://github.com/w3c/csswg-drafts/issues/13767)
- **Randomness matures in Values 5** ([#14079](https://github.com/w3c/csswg-drafts/issues/14079))
  - **Background:** CSS is gaining `random()`/`random-item()` and sibling counting; June nailed down evaluation rules.
  - **Why it matters:** new author-facing primitives — the syntax must be unambiguous before engines ship.
  - **Summary:** RESOLVED [how `random()` evaluates inside arbitrary substitution](https://github.com/w3c/csswg-drafts/issues/13662#issuecomment-4672428004) and [`sibling-index()`/`sibling-count()` failure behavior](https://github.com/w3c/csswg-drafts/issues/13736#issuecomment-4791604896); [`random-item()` weighting](https://github.com/w3c/csswg-drafts/issues/14079) is still wrestling with a `block 20%` syntax overlap, leaning toward an `if()`-like pattern.
  - **Related:** [#13662](https://github.com/w3c/csswg-drafts/issues/13662), [#13736](https://github.com/w3c/csswg-drafts/issues/13736)
- **Forms + anchor-positioning groundwork for customizable `<select>`** ([#13541](https://github.com/w3c/csswg-drafts/issues/13541))
  - **Background:** the customizable `<select>` work needs anchor-positioning primitives to place the picker.
  - **Why it matters:** this is the runway for July's `flip-self-*` keywords and `::picker(select)` — the customizable-select story developers are watching.
  - **Summary:** RESOLVED to [redefine the `<select>` position-try fallbacks](https://github.com/w3c/csswg-drafts/issues/13541#issuecomment-4732677022) and to give [`@position-try` globally-scoped names like `@keyframes`](https://github.com/w3c/csswg-drafts/issues/13567#issuecomment-4791554191).
  - **Related:** [#13567](https://github.com/w3c/csswg-drafts/issues/13567)
