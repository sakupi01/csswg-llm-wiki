This month in CSSWG

June's throughline was implementations catching up to specs, and specs reacting. Selected for developer impact rather than comment volume: the ::interest-button default reversed, scroll-driven animations got a semantics pass, Link Params reached FPWD, and randomness matured in Values 5 — while the loud-but-low-impact CSS Color 5 serialization threads are gathered under "Still contested." 28 resolutions landed across ~92 active agenda items.

Notable this month

  • ::interest-button reverses course on turning itself on (#13980)
    • Background: ::interest-button surfaces an affordance for interest invokers (interestfor). Early June RESOLVED to gate it behind an inline media condition (display: if(media())).
    • Why it matters: whether a layout-affecting control is on by default is a page-breaking decision for every author using interest invokers — a live cross-vendor question, not a detail.
    • Summary: after developer conversations at CSS Day, the group voided that resolution. LeaVerou argued authors would simply turn it off — anything that affects layout by default breaks pages, and an opt-out adds more UX noise (stray tab stops, tooltips among real targets) than it solves. How it turns on is open again (37 comments this month).
    • Related: UA-latitude vs. "layout-affecting defaults get disabled" — the tension to watch as interest invokers ship.
  • Scroll-driven animations get a semantics pass (#13817)
    • Background: several scroll/view-timeline timing rules were underspecified, producing "why did my scroll animation jump?" surprises.
    • Why it matters: these are exactly the edge cases authors hit wiring animations to scroll; the fixes change observable behavior.
    • Summary: RESOLVED — timeline-source changes apply asynchronously; auto-rewind has no effect when the timeline is unresolved with a new play-always trigger; startOffset/endOffset are nullable; scroll-timeline names are loosely matched.
    • Related: #13480, #13643, #13844, #13974, #13818
  • Link Params reaches First Public Working Draft (#14028)
    • Background: Link Params adds a param() function for parameterizing links/URLs.
    • Why it matters: a new spec crossing FPWD is the signal that a feature is officially on the standards track — worth a developer's radar.
    • Summary: RESOLVED to publish Link Params as FPWD and to require param() to carry at least two values.
    • Related: #13767
  • Randomness matures in Values 5 (#14079)
    • Background: CSS is gaining random()/random-item() and sibling counting; June nailed down evaluation rules.
    • Why it matters: new author-facing primitives — the syntax must be unambiguous before engines ship.
    • Summary: RESOLVED how random() evaluates inside arbitrary substitution and sibling-index()/sibling-count() failure behavior; random-item() weighting is still wrestling with a block 20% syntax overlap, leaning toward an if()-like pattern.
    • Related: #13662, #13736
  • Forms + anchor-positioning groundwork for customizable <select> (#13541)
    • Background: the customizable <select> work needs anchor-positioning primitives to place the picker.
    • Why it matters: this is the runway for July's flip-self-* keywords and ::picker(select) — the customizable-select story developers are watching.
    • Summary: RESOLVED to redefine the <select> position-try fallbacks and to give @position-try globally-scoped names like @keyframes.
    • Related: #13567

Still contested

  • CSS Color 5 serialization cluster — loud but low author-impact, demoted here: #14100 Example 32 outdated, #13996 color-mix() parsing, #13994 resolved value of alpha(), #14070 omissible alpha (no consensus).
  • #10579 static gamut-mapping algorithm — implementation results diverging (Firefox now implementing/benchmarking).
  • #5675 Masonry reading-order / accessibility — the long-running accessibility objection, part of the CSS Masonry story.
