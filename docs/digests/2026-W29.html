This week in CSSWG

The 2026-07-15 telecon spent its three resolutions on interop housekeeping — two "spec is right, fix the tests" calls for scroll-driven animations and one genuinely author-facing ruling: ::first-line/::first-letter won't apply inside text inputs. Around it, the customizable <select> hover debate and the border-shape design threads kept running hot.

Notable

  • ::first-line / ::first-letter won't apply inside text inputs (#13926)
    • Background: Blink half-accidentally supported ::first-line on input/textarea; the internal layout of form controls is unspecced and differs across engines.
    • Why it matters: an author-visible selector rule is now explicit — these pseudo-elements do nothing on text inputs, the same way ::before/::after don't apply.
    • Summary: in the call, lea pressed the author-expectation side ("if they're using it they're expecting it to work") while emilio argued there's no interoperable internal layout to hook them onto — password-input internals, ::placeholder interactions, none of it is specced. RESOLVED: they don't apply "for now", to be revisited once these controls have better-defined layout.
    • Related: #14190 (the flip side: making align-content center a block <button>'s content — bfgeek and emilio converged on a proposal this week)
  • Scroll-driven animations: two "fix the tests" rulings (#11644)
    • Background: Interop-2026 test work keeps flushing out places where Chromium's shipped behavior and the spec disagree — see Scroll-driven Animations.
    • Why it matters: both affect the Web Animations API surface of scroll/view timelines: ViewTimelineOptions.inset defaults to auto (which opts into scroll-padding), and shorthand serialization of coordinated value lists stays as specced.
    • Summary: RESOLVED spec is right, fix the tests for the inset default (Chrome's empty-array default was a years-old accident), and RESOLVED spec is right, fix tests, add animated-value tests for the serialization question. A third fix is queued as an async resolution: auto-aligning a start time should apply a pending playback rate.
    • Related: Scroll-driven Animations, #13500

Also active

  • #14143 :hover / :active top-layer propagation — the customizable-<select> hover debate kept going all week (19 comments): mfreed7's "popovers pretend to be the last child of <body>" framing vs emilio's "that pretence is rendering-only" pushback.
  • #13506 stroking border-shape — converging on a possible border-style: stroke opt-in that unlocks SVG-style stroke properties; #14150 deferring two-shape border-shape to L5 got pushback from noamr and tabatkins.
  • #14190 align-content on a block <button> — fresh issue, and by week's end a concrete proposal with implementer buy-in from bfgeek.
  • #14004 @locals hygienic rewriting — tabatkins and kbabbitt working through whether rewritten variable names should ever be observable.
  • #14181 a stuck range name for sticky elements and #14188 zoom × animation-range — two fresh scroll-driven-animations proposals aimed at "scrolltelling" patterns.
  • Publishing: css-link-params-1 FPWD published (2026-07-14).
