This week in CSSWG

A single telecon on 2026-07-01 produced six resolutions, clustered around forms and navigation ergonomics: anchor positioning gained self-flipping keywords wired into the <select> picker, and the navigation-source selector was broadened beyond links and given the name :nav-source. The week's loudest threads were in CSS Color 5 and, once again, Masonry.

Notable

  • Anchor positioning learns to flip against its own writing mode, and drives the <select> picker (#14062). Two resolutions landed here: to add flip-self-inline and flip-self-block to position-try and to use these values for ::picker(select). The existing flip-inline/flip-block keywords flip using the container's writing mode; fantasai noted use cases that need the element's own writing mode, and the WG agreed to add the -self- pair for consistency. Following on from #13541 and #13738, tying these to ::picker(select) connects anchor positioning to the customizable <select> work — one of the most-watched author-facing surfaces right now.
  • The navigation-source selector goes broader than links, and gets a name: :nav-source (#11801). The WG resolved that the feature applies not just to links and to add a :nav-source pseudo-class for this use case. The original :trigger-link was scoped only to <a>, but TabAtkins and fantasai pushed back that forms and submit buttons also initiate navigations, and that a link-only selector would nudge authors toward links where a form belongs. Mirroring the Navigation API's sourceElement, the name :nav-source won out over :trigger-link — though dbaron and bramus flagged that "source" could be misread as the page you came from rather than the element that triggered the navigation. This gives cross-document view-transition and scroll-restoration styling a way to target "what the user activated."
  • View Transitions: what getComputedStyle returns for a pseudo-element that doesn't exist (#13904). Resolved that non-existing pseudo-elements inherit from their ultimate originating element when you query the computed style. Prompted by a WPT that assumed a whole non-existent inheritance tree, emilio and TabAtkins argued the engine shouldn't invent the state of a tree that isn't there — instead inherit straight from the originating element. A CSSOM-correctness call, but one that pins down observable behavior for tools and tests probing view-transition pseudo trees.
  • Web Animations makes element-dependent typed values a parse error (#13853). Resolved to make it a parse error to set string values or typed CSSOM values that require an element to resolve. The setters for rangeStart/rangeEnd accept <length-percentage>, but relative units (and var(), sibling-index(), etc.) have no defined resolution context outside style resolution. Rather than pick an arbitrary element to resolve against — root vs. target vs. initial style, all judged too costly or surprising — weinig, TabAtkins and fantasai chose to reject them at parse time now and relax later once a proper processing model exists. Absolute lengths and percentages remain valid.
