This week in CSSWG

One telecon (2026-07-01) produced six resolutions, clustered on forms and navigation ergonomics: anchor positioning grew self-flipping keywords wired into the <select> picker, and the navigation-source selector was broadened beyond links and named :nav-source. Picked for what changes authoring, not for what was loudest — the week's highest-comment threads were CSS Color 5 serialization minutiae, left to the "Also active" list.

Notable

  • Anchor positioning learns to flip against its own writing mode, and drives the <select> picker (#14062)
    • Background: position-try's existing flip-inline/flip-block flip using the containing block's writing mode; this follows on from #13541 and #13738.
    • Why it matters: ties anchor positioning to the customizable <select> picker (::picker(select)) — one of the most-watched author-facing surfaces right now — and adds in-place mirroring that doesn't depend on the container's writing mode.
    • Summary: RESOLVED to add flip-self-inline/flip-self-block to position-try and to use these values for ::picker(select) — fantasai raised the element's-own-writing-mode use case, TabAtkins +1, no objection.
    • Related: #13541, #13738, CSS Anchor Positioning
  • The navigation-source selector goes broader than links, and gets a name: :nav-source (#11801)
    • Background: the original :trigger-link was scoped only to <a>; the selector targets the element that initiated an outgoing navigation, mirroring the Navigation API's sourceElement.
    • Why it matters: cross-document view-transition and scroll-restoration styling gets a way to target "what the user activated" — and since forms/submit buttons initiate navigations too, a link-only selector would have nudged authors toward links where a form belongs.
    • Summary: RESOLVED it applies not just to links and to add a :nav-source pseudo-class; the name won over :trigger-link, though dbaron and bramus flagged that "source" could be misread as the page you came from.
    • Related: css-navigation-1, selectors-5
  • Web Animations makes element-dependent typed values a parse error (#13853)
    • Background: the setters for rangeStart/rangeEnd accept <length-percentage>, but relative units (and var(), sibling-index(), …) have no resolution context outside style resolution.
    • Why it matters: closes a footgun where a value that can only resolve against a live element was silently accepted; absolute lengths and percentages stay valid.
    • Summary: RESOLVED to make it a parse error to set string or typed CSSOM values that require an element to resolve — weinig, TabAtkins and fantasai chose reject-now, relax-later once a processing model exists.
    • Related: web-animations-2
  • View Transitions: what getComputedStyle returns for a pseudo-element that doesn't exist (#13904)
    • Background: prompted by a WPT that assumed a whole non-existent pseudo-element inheritance tree.
    • Why it matters: pins down observable behavior for tools and tests probing view-transition pseudo trees.
    • Summary: RESOLVED that non-existing pseudo-elements inherit from their ultimate originating element when you query the computed style — emilio and TabAtkins argued the engine shouldn't invent the state of a tree that isn't there.
    • Related: css-view-transitions-1, cssom-1
