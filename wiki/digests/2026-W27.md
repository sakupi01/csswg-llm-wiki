## This week in CSSWG

A single telecon on 2026-07-01 produced six resolutions, clustered around
forms and navigation ergonomics: anchor positioning gained self-flipping
keywords wired into the `<select>` picker, and the navigation-source selector
was broadened beyond links and given the name `:nav-source`. The week's loudest
threads were in CSS Color 5 and, once again, Masonry.

## Notable

- **Anchor positioning learns to flip against its own writing mode, and drives
  the `<select>` picker ([#14062](https://github.com/w3c/csswg-drafts/issues/14062)).**
  Two resolutions landed here: to
  [add `flip-self-inline` and `flip-self-block` to `position-try`](https://github.com/w3c/csswg-drafts/issues/14062#issuecomment-4857805306)
  and to
  [use these values for `::picker(select)`](https://github.com/w3c/csswg-drafts/issues/14062#issuecomment-4857805306).
  The existing `flip-inline`/`flip-block` keywords flip using the *container's*
  writing mode; [fantasai](../people/fantasai.md) noted use cases that need the *element's own* writing
  mode, and the WG agreed to add the `-self-` pair for consistency. Following on
  from [#13541](https://github.com/w3c/csswg-drafts/issues/13541) and
  [#13738](https://github.com/w3c/csswg-drafts/issues/13738), tying these to
  `::picker(select)` connects anchor positioning to the customizable `<select>`
  work — one of the most-watched author-facing surfaces right now.
- **The navigation-source selector goes broader than links, and gets a name:
  `:nav-source` ([#11801](https://github.com/w3c/csswg-drafts/issues/11801)).**
  The WG resolved that the feature
  [applies not just to links](https://github.com/w3c/csswg-drafts/issues/11801#issuecomment-4857772799)
  and to
  [add a `:nav-source` pseudo-class for this use case](https://github.com/w3c/csswg-drafts/issues/11801#issuecomment-4857772799).
  The original `:trigger-link` was scoped only to `<a>`, but [TabAtkins](../people/tabatkins.md) and
  [fantasai](../people/fantasai.md) pushed back that forms and submit buttons also initiate navigations,
  and that a link-only selector would nudge authors toward links where a form
  belongs. Mirroring the Navigation API's `sourceElement`, the name `:nav-source`
  won out over `:trigger-link` — though [dbaron](../people/dbaron.md) and [bramus](../people/bramus.md) flagged that "source"
  could be misread as *the page you came from* rather than the element that
  triggered the navigation. This gives cross-document view-transition and
  scroll-restoration styling a way to target "what the user activated."
- **View Transitions: what `getComputedStyle` returns for a pseudo-element that
  doesn't exist ([#13904](https://github.com/w3c/csswg-drafts/issues/13904)).**
  Resolved that
  [non-existing pseudo-elements inherit from their ultimate originating element when you query the computed style](https://github.com/w3c/csswg-drafts/issues/13904#issuecomment-4858013386).
  Prompted by a WPT that assumed a whole non-existent inheritance tree, [emilio](../people/emilio.md)
  and [TabAtkins](../people/tabatkins.md) argued the engine shouldn't invent the state of a tree that
  isn't there — instead inherit straight from the originating element. A
  CSSOM-correctness call, but one that pins down observable behavior for tools
  and tests probing view-transition pseudo trees.
- **Web Animations makes element-dependent typed values a parse error
  ([#13853](https://github.com/w3c/csswg-drafts/issues/13853)).** Resolved to
  [make it a parse error to set string values or typed CSSOM values that require an element to resolve](https://github.com/w3c/csswg-drafts/issues/13853#issuecomment-4857950246).
  The setters for `rangeStart`/`rangeEnd` accept `<length-percentage>`, but
  relative units (and `var()`, `sibling-index()`, etc.) have no defined
  resolution context outside style resolution. Rather than pick an arbitrary
  element to resolve against — root vs. target vs. initial style, all judged too
  costly or surprising — weinig, [TabAtkins](../people/tabatkins.md) and [fantasai](../people/fantasai.md) chose to reject them at
  parse time now and relax later once a proper processing model exists. Absolute
  lengths and percentages remain valid.
